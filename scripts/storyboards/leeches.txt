# The **caught-up floor with its one control**, and the **leech screen** behind it (ADR-0010 §6, §8).
#
# The same floor as `caught-up.txt`, with three cards over the leech floor — which is the only way
# the screen carries a control at all, and therefore the only state in which ADR-0035 §1's reach line
# has a second call site to be judged against (#155 owes that amendment).
#
# Reaching it needs a card **failed four times and then recovered**: a card whose latest grade is a
# failure is due whatever its interval says, so a leech that merely failed its way over the floor
# would put the screen back into the card state. That is why this is a fixture and not a storyboard
# that grades a few cards.
fixture leeches
# The first click is spent giving the window keyboard focus and never reaches a widget, so it is
# aimed at empty space.
mousemove %CX% 600 click 1
sleep 1
shot 02-caught-up-with-leeches
# The durable entrance — full width, so `%CX%` reaches it at any width.
#
# **`%BY-183%`, not a literal y, and #155 is why.** This line read `252` — measured off the capture
# above, back when the entrance sat directly under the statement. ADR-0038 §5 put it on ADR-0035
# §1's reach line instead, which makes its position **height-dependent**: 165px for the reach line
# plus half of `controls::HEIGHT`. A literal y then reaches empty page at every window size, and the
# run produces a perfectly valid capture of the *caught-up* screen under the leech screen's name —
# the silent miss arriving for the fourth time, from the axis
# [#154](https://github.com/amin-bf/cairn/issues/154) added `%BY-n%` to close.
mousemove %CX% %BY-183% click 1
sleep 1.2
shot 03-leech-screen
