# Persian into the note editor, and the mixed-direction case beside it.
#
# `xdotool type` remaps keysyms to reach characters the layout does not carry, so what this exercises
# is the **keymap** path — the same events an `ir(pes)` layout produces, delivered as ordinary key
# presses. It does **not** exercise a composing input method (`zwp_text_input_v3`); Persian does not
# need one, but see `docs/environment/desktop-capture.md` for what that leaves unproven.
#
# **The nav x is `%LX+86%`, not a literal 86.** It was a literal until #132, and it had been missing
# its target since #131 put a 28px page margin in front of it — the click landed on *Review*, so this
# storyboard photographed the Review screen three times under three editor names and said nothing.
# `baseline.txt` was migrated to `%LX%` when the frame landed and this file was not; that is the whole
# failure. A storyboard cannot tell you it missed (#122), so both files are now on the same token.
#
# **Everything inside the editor is `%EX+n%`, not `%CX%`** (#163). The editor is the one screen with
# its own frame — `frame::cap_for` gives it 1120 — so `%CX%` is inside a field at the 560 this file is
# run at and lands fourteen pixels past its right edge at 1280. It has been correct here and wrong
# anywhere else since #131, which is the same latent miss the nav x above had actually taken; the
# token removes it before it is paid for rather than after.
#
# **The y's are the two-column arrangement's, which is now the only one the desktop has.** #163
# deleted `TWO_COLUMN_MIN_WIDTH` — the editor folds its panes into a toggle where a soft keyboard
# eats the height, not where a window is narrow — so there is one vertical stack at every width and
# these coordinates hold at all of them. This file is still *run* at 560×860, because that is the
# window its shots were composed against, not because it would miss anywhere else.
mousemove %CX% 600 click 1
sleep 1
mousemove %LX+86% 11 click 1
sleep 1.2
mousemove %CX% 87 click 1
sleep 1.5
mousemove %EX+30% 229 click 1
sleep 0.8
sh xdotool type --delay 120 'سگ در خانه است.'
sleep 1.5
shot 08-editor-persian-front
mousemove %EX+30% 265 click 1
sleep 0.8
sh xdotool type --delay 120 'the dog is in the house'
sleep 1.5
shot 09-editor-persian-and-latin
# The **card pane**, which is the only place a storyboard can reach Persian drawn at the display tier
# — 40px is a size no other screen in this set draws, and the card face is the one surface that uses
# it (ADR-0032 §1). Client-stack rule 7 makes this worth a capture rather than an assumption: within
# a family the *first* matching face wins, more than one shipped face carries the Arabic script, and
# a glyph existing is not the same as the right face drawing it. Nothing but looking tells them apart.
#
# **It needs no tap now.** This used to click the `Write | Cards` toggle, because at 560 the editor
# folded its panes; #163 made that fold a question about the platform's soft keyboard rather than
# about the window, so the desktop draws both panes at every width and the card is already on screen.
# Blurring into empty page is what settles the field and redraws it (ADR-0021 §7).
mousemove %CX% 500 click 1
sleep 1.2
shot 11-cards-persian-display
# *Done* is on ADR-0035 §1's reach line since #163, so its y follows the window height.
mousemove %EX+60% %BY-184% click 1
sleep 1.5
shot 10-notes-list-with-persian
