# The same screens as `baseline.txt`, in the **light** appearance (ADR-0036).
#
# It switches the theme through the real control on Settings rather than through a test hook, which
# is deliberate: the appearance is a stored, device-local preference, so a capture that forced it
# some other way would photograph a state the application cannot actually be put into. It also means
# this storyboard fails loudly if `theme_control` stops working, where an env override would keep
# producing light pictures of a broken control.
#
# **Settings is visited first, and that is the whole reason the order differs from `baseline.txt`.**
# Every screen after the switch is drawn light; anything captured before it would be whatever the
# host's System preference resolves to, which is not reproducible between machines.
#
# `%CX%` is the centre of the output; `%LX+n%` is `n` px inside the page frame's left edge (#131).
#
# The first click is spent giving the window keyboard focus and never reaches a widget, so it is
# aimed at empty space.
mousemove %CX% 600 click 1
sleep 1
# Settings. The nav row sits above the frame's content but aligns to the same left edge.
mousemove %LX+140% 11 click 1
sleep 1.2
# **Appearance: Light.** `System` `Light` `Dark`, drawn with `selectable_label` the same way the nav
# marks the current destination. `+84` is the centre of `Light`, measured off the capture rather than
# computed — the row is frame-relative, so the same offset lands at both widths.
#
# **y=93 is the same at 1280 and at 560, and the control was moved to the top of Settings to make
# that true.** The first draft of this storyboard clicked it where it sat below the new-card-rate
# prose, which wraps to two lines at 560 — so the click landed on the right control at one width and
# on empty page at the other, and the run produced seven perfectly valid *dark* captures with
# nothing failing. Only the heading is above it now, and a one-word heading cannot wrap.
mousemove %LX+84% 93 click 1
sleep 1.5
