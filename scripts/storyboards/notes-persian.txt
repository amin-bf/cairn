# The Notes destination in **Persian** — the editor's fields and card face, and a note-list row.
#
# **Runs at any width, and the two things that stopped it are both gone.**
#
# This is the one storyboard in the set that has to aim at a control *inside* the editor, and the
# editor takes its own wider frame (#131, `frame::cap_for` → 1120) — so its column starts at x=80 at
# 1280 where the list's starts at 320, and `%LX+n%` is the wrong frame here however right it is in
# the nav row. `%CX%` — 640 — reaches a field at 560 and lands **fourteen pixels past its right edge**
# at 1280: `persian.txt` aimed that way and had been missing since #131, and the first run of this
# file did the same, typed nothing, and photographed the French note under the Persian name. #163
# spent `%EX+n%` on that rather than keeping the caveat, and every x below is right at any width.
#
# The **y** then pinned it to 1280 for one more round, and that is the interesting half. Below the old
# `TWO_COLUMN_MIN_WIDTH` the editor inserted the `Write | Cards` toggle, which pushed both fields
# down by a row — so at 560 the x landed correctly and y=265 fell in empty page while y=300 found
# *Front*, and the run overwrote `l'aube` with the Back string and left `dawn` behind it. Same
# silent-miss class as the x, arriving from the **vertical** axis, and caused by an arrangement
# change rather than by a frame or a coordinate.
#
# #163 deleted that arrangement change: the toggle is a question about the platform's soft keyboard
# now, not about the window, so the desktop has **one** vertical stack at every width and the field
# y's below are the same at 560 as at 1280. The pin went with the width it was made of.
#
# **Both shots are self-evidencing** and stay worth checking: a run that missed leaves
# `06-editor-persian` showing `l'aube` / `dawn`, and leaves `07-list-persian` with no Persian row.
fixture backlog
mousemove %CX% 600 click 1
sleep 1
mousemove %LX+86% 11 click 1
sleep 1.2
mousemove %LX+200% 259 click 1
sleep 1.5
# The editor's Front field starts at the editor frame's own left edge, so `%EX+30%` is inside it at
# every width — 110 at 1280 and 58 at 560 — where `%LX+30%` is inside it only above the two-column
# threshold and `%CX%` is inside it only below. `xdotool type` remaps keysyms to reach characters the
# layout does not carry, so what this exercises is the **keymap** path — the same events an `ir(pes)`
# layout produces — and not a composing input method, which #129 ruled out of scope.
mousemove %EX+30% 265 click 1
sleep 0.5
key ctrl+a
sh xdotool type --delay 80 'سپیده‌دم'
sleep 0.8
mousemove %EX+30% 300 click 1
sleep 0.5
key ctrl+a
sh xdotool type --delay 80 'آغاز روز، پیش از برآمدن خورشید'
sleep 1
# Blur into empty page so the field autosaves (ADR-0021 §7) and the card pane redraws. The card face
# is the only place a storyboard reaches Persian at the display tier, and client-stack rule 7 makes
# that worth a capture rather than an assumption: within a family the first matching face wins, more
# than one shipped face carries the Arabic script, and nothing but looking tells them apart.
mousemove %CX% 500 click 1
sleep 1.5
shot 06-editor-persian
# Back to the list by *Done*, which starts at the editor frame's left edge in both arrangements —
# compact above the two-column threshold and full-width below it, so `%EX+60%` is inside it either
# way. Clicking the nav row's *Notes* does not work here: it is the current destination, so the click
# is a no-op and the next shot is the editor again under the list's name.
mousemove %EX+60% 49 click 1
sleep 1.5
# The row this produces is the one #162 redrew. It used to be the defect this comment named — the
# button allocated 61px at x=318..378 with the glyphs drawing from x=274, so the word sat outside
# both its own control and the page margin — which `fc4e129c` fixed ahead of that ticket. What it
# shows now is ADR-0039 §4: the row is a full-width band, so it has an **end** for the first time,
# and the text mirrors to the note's own direction while the action column stays put.
shot 07-list-persian
